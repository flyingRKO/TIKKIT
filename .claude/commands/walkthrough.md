# Claude 명령어: Walkthrough

이미 작성된 코드를 사용자가 직접 파악할 수 있도록, 요청 흐름 순서대로 짚어주고 확인 질문까지 하는 명령어입니다.
코드를 새로 작성하지 않습니다. 읽고 설명만 합니다.

## 사용법

```
/walkthrough 012        # Task 012 커밋 워크스루
/walkthrough #6          # PR 번호로 워크스루
/walkthrough a1b2c3d      # 커밋 해시로 워크스루
/walkthrough              # 인자 없으면 main..HEAD + 커밋 안 된 변경
```

## 대상 찾기

- 3자리 숫자(예: `012`) → `git log --all --grep "Task 012"`로 해당 커밋 찾기
- `#숫자` → `gh pr view <숫자>` / `gh pr diff <숫자>`로 PR 변경사항 가져오기
- 커밋 해시 → `git show <hash>`
- 인자 없음 → `git diff main..HEAD`와 `git status`의 커밋 안 된 변경 둘 다 대상

## 진행 순서

1. **전체 그림**: 이 변경이 뭘 하는지 3~4줄로 요약, 바뀐 파일 목록 (레이어별로 묶어서)
2. **요청 흐름 다이어그램**: 실제 요청/데이터가 어떤 순서로 어떤 파일을 지나가는지
   - 예: `POST /reservations → ReservationController → ReservationService → Reservation 엔티티 메서드 → ReservationRepository → DB`
3. **흐름 순서대로 파일별 설명**: 다이어그램 순서를 따라 파일 하나씩
   - 이 파일의 역할이 뭔지
   - 핵심 코드는 `파일:라인` 형태로 인용 (전체 파일을 그대로 붙여넣지 않는다, 중요한 부분만)
   - 왜 이렇게 짰는지, 다른 선택지는 뭐가 있었는지
   - 불확실하거나 알려진 한계가 있으면 명시 (예: 동시성 미보장 지점)
4. **테스트**: 테스트 코드가 있으면 뭘 검증하는지 간단히
5. **확인 질문**: 방금 훑은 내용 기준으로 면접식 질문 3~5개를 던지고, 사용자가 답하면 채점하고 부족한 부분을 보충 설명

## 진행 방식

- 내용이 길면 섹션(위 1~5) 단위로 끊어서 보여주고, 사용자가 "다음"이라고 하면 이어서 진행
- 사용자가 특정 파일/라인에 대해 더 물어보면 그 자리에서 답하고, 필요하면 관련 파일을 추가로 열어서 보여줌
- 개발일지 소재가 될 만한 결정(동시성, 트랜잭션, 인증 등)을 다뤘으면 마지막에 `📝 일지 후보: <주제>` 한 줄만 남긴다 (CLAUDE.local.md 규칙대로, 사용자가 명시적으로 요청하기 전엔 파일을 쓰지 않음)
