# 고도화 기록 인덱스

각 문서는 **재현 → 해결 → 수치** 순서로 쓴다. 기각한 것도 같이 남긴다 — 왜 안 썼는지가 왜 썼는지보다
자주 필요하다.

## 문서 번호와 Task 번호가 어긋나 있다

문서 번호는 **주제 순서**이고 Task 번호는 **작업 순서**다. Phase 7에서 선행 작업을 뒤늦게 문서화해
`004_1`~`004_3`이 생겼고, Phase 8의 FE 작업이 셋으로 쪼개져 `009`~`009_2`가 생겼다.
그래서 대응 표가 필요하다.

## 이 기록들을 꿰는 교훈 다섯

세 Phase를 지나며 같은 함정을 반복해서 밟았다. 순서대로 읽으면 하나의 이야기가 된다.

1. **수치가 좋아지는 가장 흔한 이유는 요청이 일을 안 한 것이다.** 007은 버퍼를 88% 줄였는데
   빨라지지 않았고, 010은 좌석 조회가 전부 403이 되면서 p95가 64 → 2.95ms로 "개선"됐다.
   그래서 하네스에 **워크로드 무결성 검사**(iteration당 요청 수·수신 바이트)가 들어갔다 —
   붕괴하면 지연이 좋아지므로 지연 임계값은 오히려 통과한다.

2. **저부하 p95로 채택/기각하지 않는다.** 008이 캐시를 "지연은 그대로지만 용량 때문에 채택"으로
   남겼고, 010이 포화까지 올려 +37%를 확인했다. 008이 용량을 재지 못한 **구조적 이유**는
   하네스의 think time이 iteration의 99.8%였다는 것이다(010 8.1절).

3. **측정 지점이 하나면 결론이 뒤집힌다.** 009_2의 같은 변경이 2,000석에서는 회귀, 10,000석에서는
   개선이었다. 010도 깊이 1,000과 100,000을 둘 다 재서 외삽을 정당화했다.

4. **반증된 설명을 코드 주석에 남기면 다음 사람이 그걸 근거로 움직인다.** 010에서 커넥션 풀이
   벽이라고 쓴 주석과 ETA가 `fixedDelay` 때문에 낙관적이라는 주석을 둘 다 실측이 뒤집었고,
   수치뿐 아니라 **그 주석들을 같이 고쳤다.**

5. **기각한 구현은 토글로도 남기지 않는다.** 009_1의 gzip, 003의 Redisson, 010의 좌석 응답 축소를
   모두 코드째 지웠다. 검증되지 않은 코드가 계약에 남으면 다음 사람이 그게 유효한 선택지라고 읽는다.

## 다음 후보

각 문서 "다음 단계" 절의 `[미배정]` 항목이 출처다. **ROADMAP Phase 11에서 번호를 받았다.**

- **[Task 036] 좌석맵 조립 비용 줄이기** — 좌석맵 요청의 68%가 DB 조회 + DTO 조립이다. 008이 Caffeine 로컬
  캐시를 기각한 근거가 Redis의 역직렬화 비용이었다면 **로컬 캐시에는 적용되지 않는다** (010 9.2·15절)
- **[Task 037] `admit-batch-size`를 전역 상한으로** — 지금은 회차당이라 켠 회차 수에 비례해 입장 속도가
  올라간다 (010 5.2절)
- **[Task 037] 세션 Redis 분리 판단** — 메모리 압박의 1차 희생자가 세션이다 (010 7.2절)
- **[Task 040] 007 커버링 인덱스 재판정** — 포화 하네스가 이제 있다. `shared_buffers` 기본 128MB
  상향을 같이 잰다 — 007이 "인덱스보다 효과가 클 수 있는데 측정하지 않았다"고 남긴 항목이다
- **[Task 039] 009_1 gzip 재판정 · HTTP/2** — 둘 다 "Task 034(클라우드 배포)를 기다린다"로 적어 뒀지만
  **기다릴 필요가 없다.** gzip의 재판단 조건은 포화 구간이고 그 하네스는 010이 만들었다. HTTP/2는
  TLS가 선행인데 로컬 self-signed로 세울 수 있다 (평문 h2c는 브라우저가 지원하지 않아 쓸 수 없다)
- **[Task 035] 좌석 선택 레이어 오버레이** — 10,000석 클릭당 32.5ms. `includes()`가 좌석마다 O(n)이다
  (009_2). **Phase 11에서 가장 큰 레버이고 부하 노드 없이 닫을 수 있는 유일한 항목이다**
- **[Task 038] 전용 부하 노드** — 부하 생성기가 측정 대상과 같은 호스트에 있어서 `R_poll`이 하한으로만
  남았다(006·010). **장비가 선행이라 로컬에서는 닫을 수 없고, 위 Task들이 이 한계를 안고 측정한다**
